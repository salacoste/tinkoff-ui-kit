# UX-DR17 yellow-discipline audit — v2 extension (Story 8.4, 2026-09-25)

**Standard (тот же, что v1-аудита — `../fidelity-verification/yellow-audit.md`):**
жёлтый ТОЛЬКО для primary-action заливок и активных индикаторов; чернильный
текст на жёлтом (никогда белый); жёлтый никогда для ссылок/иконок-в-покое/
декораций; активные индикаторы всегда избыточны весом, тенью или другим
нечувствительным-к-цвету носителем (WCAG 1.4.11).

**Расширение этой историей:** v1-аудит покрыл 19 компонентов и доки 5.5.
Здесь — v2-ноги: девять v2-компонентов, три композиции, страницы доков v2
(8.3). Методология v1 дословно: механический grep → классификация каждого
потребляющего селектора → утверждение ink-on-yellow. Аудит МОЖЕТ падать —
v1-прогон нашёл и исправил 2 реальных нарушения (F1/F2); этот прогон
воспроизводит ту же команду.

## Step 1 — жёлтые токены (не изменились с v1)

`--tk-color-yellow-100 #FFDD2D / -200 #FCC521 / -300 #FAB619` — theme-
invariant (тёмного переопределения нет). Ни один другой токен не резолвится
в жёлтый hex (сгенерированный листинг; consumed-tokens CI-гард доказывает
резолв каждого `var(--tk-*)`). 6.1 добавил v2-семантики (warm-cream, delta,
table) — НИ ОДНА не указывает на жёлтые.

## Step 2 — механическая инвентаризация (v2-ножи)

Команда v1 дословно (65 хитов в 28 файлах на aa9780f; полный список — grep,
ниже — только ПОТРЕБЛЯЮЩИЕ селекторы v2-эпохи; jsdoc/проза упомянуты классом
«документация»): сырые hex-литералы жёлтого (`#FFDD2D|#FCC521|#FAB619|
255,221,45`) вне сгенерированного токен-листа — **1 хит, комментарий**
(thumbnail-picker.css.ts:13, документация пробы).

## Step 5 — ink-on-yellow (никогда белый) — новые поверхности

| Поверхность | Носитель текста | Значение | Утверждено |
|---|---|---|---|
| tk-pagination активная пилюля | `.page__pill` color | ink-300 #333333 | в-коде (pagination.css.ts:147) + пиксель-проба 9.3:1 (NOTES) + dark-движок FORCE |
| cookie-banner hooks-демо | `--tk-cookie-banner-accept-text` | ink-300, инлайн в том же блоке | самим объявлением |
| logo-щиты ×3 | текст щита | ink-400 | исходники историй |
| filter-chips выбранный чип | текст чипа | text-primary #333 на БЕЛОЙ заливке (жёлтая — только рамка) | strip-scope; текст на жёлтом не возникает |

Белый (или white-семейство) цвет текста на жёлтой заливке не объявлен ни в
одном новом селекторе — перекрёстная проверка grep-ом текстовых правил
каждого жёлтого потребителя. Тёмный слой: yellow-100 без override — пары
инвариантны (8.2-движок, 28/28).

## Вердикт

- Новые primary-CTA заливки в ХРОМЕ кита: **0** (демо A5 — документированный
  канал, парность инлайн).
- Новые активные индикаторы: **2** (B4/B5) — легальны, носители-партнёры
  названы в обеих строках.
- Новый демо/арт: **5** (C8–C12) — consumer-content класс, парность где есть
  текст.
- **Незаконных: 0 найдено → 0 исправлений.** Аудит воспроизводим той же
  командой (Step 2 v1-файла + сырой-hex свип); его способность падать
  доказана v1-прогоном (F1/F2, исправлены в-change) — та же механика, тот же
  порог.

UX-DR17 держится kit-wide на v2-ножах: жёлтый в v2-эпохе появился ТОЛЬКО как
(а) активная страница пейджера, (б) рамка выбранного чипа, (в) арт/лого
слотов и hooks-демо. Ни ссылок, ни иконок-в-покое, ни декоративных полос.
