От дизайн-источника до React-пропсов — один конвейер

В ките ничего не синхронизируется руками. Каждый слой генерируется из нижележащего и гейтится в CI — так 56 компонентов держат один дизайн-язык релиз за релизом.

  1. 01 packages/tokens · DESIGN.md

    Дизайн-источник

    Отступы, типографическая шкала, цвет, радиусы и движение измерены на эталонных поверхностях и сведены в единый DESIGN-источник. CI падает на захардкоженных значениях внутри пакетов — дрейф не проходит.

  2. 02 pillkit-tokens · pillkit-tj-tokens

    Токеновый слой

    258 CSS custom properties (151 --tk-* + 107 --tj-*) компилируются в обычный CSS: светлая и настоящая тёмная тема в одном слое, ноль рантайм-JavaScript на пути темизации.

  3. 03 pillkit-components · pillkit-tj-components

    Компоненты

    56 Lit 3 custom elements (46 tk-* + 10 tj-*) в shadow DOM — TypeScript, семантика APG и один общий overlay-контроллер для всего, что всплывает над страницей.

  4. 04 pillkit-react · pillkit-tj-react

    React-поверхность

    51 обёртка генерируется из Custom Elements Manifest: типизированные пропсы, развёрнутые полезные нагрузки событий, React 18 и 19. React-API не может разойтись с Lit-ядром.

  5. 05 pillkit-docs

    Документация и гейты

    Storybook 10 с API-справочником и заметками о доступности по каждому тегу — и 2 755 автоматических визуальных и axe-проверок против закоммиченных базлайнов на каждом пуше.

Два независимых семейства: банковский регистр (tk-*) и редакционный суб-кит (tj-*) не делят ни код, ни токены — берите одно, не вытаскивая второе.

Фреймворк-агностичен по построению

Кит — это Lit 3 custom elements плюс обычные CSS custom properties: любой современный фреймворк потребляет их нативно. React дополнительно получает сгенерированные обёртки с типизированными пропс и развёрнутыми полезными нагрузками событий.

React 18 / 19

Обёртки генерируются из Custom Elements Manifest — пропсы и события не могут разойтись с Lit-ядром по построению.

Vue 3

Custom elements — полноправные жители шаблонов: зарегистрируйте один раз, используйте теги tk-* где угодно.

Svelte

Адаптер не нужен — теги компилируются прямо в разметку и уходят в продакшен как есть.

Angular

Потребляет custom elements нативно: объявите CUSTOM_ELEMENTS_SCHEMA и работайте с tk-* как с любым элементом.

Ваниль / статический HTML

Импортируйте пакет, напишите разметку — всё. Страница, которую вы читаете, устроена именно так.

Любой стайлинг

Токены — обычные CSS custom properties: переопределяйте, мостите в утилитарные фреймворки, темизируйте по поверхностям.

SSR: Lit 3 поддерживает серверный рендеринг через @lit-labs/ssr, а токеновый слой — обычный CSS, который уходит клиенту как есть; рантайм-JS для темы не нужен ни там, ни там.

Сделано как производственная инфраструктура

Профессионализм — это не покрытие, а конвейер за каждым пикселем. Эти гарантии исполняются на каждом пуше, а не в день релиза.

Доступность на первом месте

Контрастная книга AA, axe-прогоны в обеих темах, семантика для скринридеров, полный клавиатурный паритет и reduced-motion в каждом компоненте.

Настоящая тёмная тема

Один атрибут — data-theme="dark" — перестраивает семантический слой токенов; тени схлопываются в тональную высоту. Второй стилевой таблицы и веток в коде нет.

Токеновый конвейер, а не зоопарк hex-ов

258 токенов генерируются из единственного источника DESIGN; CI падает на захардкоженных значениях внутри пакетов — дрейф не проходит.

Верификация на каждом пуше

2 755 автоматических визуальных и axe-проверок сравнивают каждый компонент с закоммиченными кроссплатформенными базами — в светлой и тёмной темах.

Сгенерированная React-поверхность

Обёртки выходят из Custom Elements Manifest, поэтому React-API не может разойтись с Lit-ядром; события приходят с развёрнутыми payload-ами.

Общий overlay-контроллер

Модалки, поповеры, тултипы и тосты делят один z-порядок и дисциплину возврата фокуса — стекинг-контексты не конфликтуют.

Где применять

Четыре поверхности, из которых регистры извлечены, — и где они окупаются с первого дня.

Финтех-дашборды и онбординг

Таблицы данных, фильтры, многошаговые флоу и KYC-формы — регистр, из которого кит и реверс-инжинирился.

Админ-консоли

Плотные таблицы, тулбары, реестры настроек и статус-бейджи, которые выдерживают настоящие операционные данные.

Редакция и медиа

Суб-кит tj-* с нулевыми зависимостями: типографика лонгридов, врезки и карточки статей для контентных поверхностей.

Маркетинговые лендинги

Hero-контролы, бейджи, скелеты и тосты, совпадающие с продуктовым UI пиксель-в-пиксель — включая эту страницу.

Вкус API

Один компонент — две поверхности: custom element и сгенерированная React-обёртка. Кит ставится pnpm-линком воркспейса из запиненного релизного тега; полный рецепт — в быстром старте README.

index.html — любой фреймворк 
<!-- токены один раз, компоненты один раз -->
<!-- дальше разметка и есть API -->
<tk-button variant="primary" size="hero">Открыть счёт</tk-button>

<tk-input label="Email" placeholder="name@example.com"></tk-input>
App.tsx — React-обёртка 
// сгенерировано из Custom Elements Manifest
import 'pillkit-tokens/tokens.css';
import 'pillkit-components';
import { Button, Input } from 'pillkit-react';

<Button variant="primary" size="hero">Открыть счёт</Button>
<Input label="Email" placeholder="name@example.com" />
