Витрина семейства · консольный регистр

Семейство Админ

Те же 46 атомов tk-* — консольным акцентом. Регистр для внутренних инструментов, бэк-офисных консолей и дашбордов: плотные данные, хром-табы со счётчиками и обратная связь на каждом асинхронном действии. Всем по-прежнему правит один токенный слой: переключите тему кнопкой в шапке — перекрасится вся консоль. Всё ниже живое.

Хром-табы консоли

Вторичная навигация авторизованной зоны: подчёркивание-индикатор и монохромные счётчики-бейджи держат ритм тихим, пока очереди меняют размер.

Переключатель очередей со счётчиками

Рабочая очередь: 48 документов за день, старший ждёт 26 минут.

Пять документов ждут второй подписи до отсечки в 18:00.

Исполненные и отклонённые документы на время аудиторского окна.

indicator="underline" плюс серые хуки --tk-badge-* на предке tk-tabs превращают продуктовые табы в хром-табы.

Код 
<tk-tabs indicator="underline" class="console-tabs">
  <div slot="tab-0"><p>…панель очереди…</p></div>
  <div slot="tab-1"><p>…панель подписи…</p></div>
</tk-tabs>

<style>
  .console-tabs {
    --tk-badge-fill: var(--tk-color-gray-100);
    --tk-badge-text: var(--tk-color-gray-600);
  }
</style>

<script type="module">
  document.querySelector('.console-tabs').tabs = [
    { value: 'queue', label: 'Очередь', badge: 48 },
    { value: 'sign', label: 'На подпись', badge: 5 },
    { value: 'archive', label: 'Архив' },
  ];
</script>

Данные

Сердце консоли: типографическая таблица с финансовыми ячейками и бейдж-шкала для статусов, которые ячейка не тонирует. Здесь строки инертны; href превращает их в ссылки, когда реестру нужна навигация.

Очередь платежей

.columns + .rows: двухстрочные ячейки, буквенные лого из тикера, цвета дельт на возвратах и поступлениях.

Шкала статусов

На подписи Исполнен Отклонён +3.8%

одна грамматика статусов для фильтров, тулбаров и шапок таблиц — без второго оттенка смысла на экран.

Код 
<tk-data-table id="queue"></tk-data-table>
<tk-badge variant="neutral">На подписи</tk-badge>
<tk-badge variant="attention" count="3"></tk-badge>

<script type="module">
  const queue = document.getElementById('queue');
  queue.columns = [
    { key: 'doc', header: 'Документ', width: '1.4fr' },
    { key: 'party', header: 'Контрагент', width: '1.2fr' },
    { key: 'amount', header: 'Сумма', align: 'end' },
    { key: 'status', header: 'Статус', align: 'end' },
  ];
  queue.rows = [
    { doc: { primary: 'Платёжное поручение 8-4471', secondary: '6 окт · 10:12' },
      party: { primary: 'ООО «Тюльпан»', secondary: 'TLP', logo: 'letter' },
      amount: { primary: '12 400 ₽' },
      status: { primary: 'На подписи' } },
  ];
</script>

Тулбар

Одна плотная полоса над данными: поиск, главное действие и переливающиеся команды за кебабом — цели по 44px сохраняются даже в компактном размере.

Тулбар реестра

Новый платёж Экспорт реестра в CSV Подписать выбранные Отменить выбранные

type="search" + sr-only label держат полосу визуальной; aria-label кебаба заменяет отсутствующий текст.

Код 
<div class="toolbar">
  <tk-input type="search" sr-only label="Поиск по реестру" placeholder="Документ, контрагент"></tk-input>
  <tk-button variant="primary" size="compact">Новый платёж</tk-button>
  <tk-menu-popover label="Команды реестра">
    <tk-button slot="anchor" variant="secondary" size="compact" aria-label="Ещё команды">…кебаб…</tk-button>
    <tk-menu-item>Экспорт реестра в CSV</tk-menu-item>
    <tk-menu-item variant="destructive">Отменить выбранные</tk-menu-item>
  </tk-menu-popover>
</div>

Пустые состояния и загрузка

Консоль живёт в ожидании. Скелетоны держат геометрию будущей таблицы, спиннеры помечают блокирующее действие, а пустое состояние объясняет, почему здесь ничего нет — компактируется хуками до консольной плотности.

Реестр грузится

скелетон повторяет ритм строк таблицы — вёрстка не прыгает, когда данные приходят.

Блокирующее действие

Подписываем 5 документов

loading на кнопке — для самого действия; голый спиннер — для областей, обновляемых на месте.

Пустой реестр

Все документы 6 октября исполнены. Новые появляются здесь автоматически.

Контракт пустых состояний в доках

--tk-empty-state-disc-size/gap/text-gap сжимают маркетинговый дефолт в консольный блок.

Код 
<tk-skeleton variant="line" width="100%"></tk-skeleton>
<tk-button variant="primary" loading>Подписываем 5 документов</tk-button>
<tk-empty-state class="console-empty" heading="В очереди ничего нет">
  <p slot="description">Все документы 6 октября исполнены.</p>
</tk-empty-state>

<style>
  .console-empty {
    --tk-empty-state-disc-size: 72px;
    --tk-empty-state-gap: var(--tk-space-12);
    --tk-empty-state-text-gap: var(--tk-space-8);
  }
</style>

Подтверждения

Деструктивные действия консоли подтверждаются модалкой, а результат доносится тостом — фокус возвращается на триггер в обоих случаях, так что оператор с клавиатуры не теряет место в очереди.

Отмена документов

Отменить 2 выбранных

Esc и скрим закрывают безопасно; последствие несёт деструктивная кнопка, а не вёрстка.

Тосты-исходы

Успешный исход Ошибочный исход

общий стек держит три последних; ошибки, которые надо читать, получают длиннее duration.

Код 
<tk-modal id="cancel" heading="Отменить 2 выбранных документа?">
  <p>Контрагенты получат уведомления. Отменить из очереди это нельзя.</p>
  <tk-button slot="actions" variant="secondary">Оставить</tk-button>
  <tk-button slot="actions" variant="primary">Отменить документы</tk-button>
</tk-modal>

<script type="module">
  document.getElementById('cancel').open = true;
</script>

Ориентирование

Глубоким консолям нужны обе шкалы: хлебные крошки говорят, где в иерархии вы, пагинатор — где в наборе данных; по одному событию у каждой, без перезагрузок.

Крошки + пагинатор

show-more рисует полосу «загрузить следующий кусок» рядом с переходами страниц — выбирайте одну на реальный датасет, не обе.

Код 
<tk-breadcrumb id="crumbs" label="Вы здесь"></tk-breadcrumb>
<tk-pagination count="48" default-page="3" show-more more-label="Загрузить ещё 20"></tk-pagination>

<script type="module">
  document.getElementById('crumbs').items = [
    { label: 'Консоль', href: '/tinkoff-ui-kit/ru/admin.html' },
    { label: 'Платежи' },
    { label: 'Реестр 6 октября' },
  ];
</script>

Оба платёжных поручения останутся в архиве, контрагенты получат уведомления. Вернуть их в очередь нельзя.
