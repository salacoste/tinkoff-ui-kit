Framework-agnostic by construction

The kit is Lit 3 custom elements plus plain CSS custom properties — every modern framework consumes that natively. React additionally gets generated wrappers with typed props and unwrapped event payloads.

React 18 / 19

Generated from the Custom Elements Manifest — props and events stay in sync with the Lit core by construction.

Vue 3

Custom elements are first-class template citizens — register once, use tk-* tags anywhere.

Svelte

No adapter needed — the tags compile straight into your markup and ship as-is.

Angular

Consumes custom elements natively; declare CUSTOM_ELEMENTS_SCHEMA and treat tk-* like any other element.

Vanilla / static HTML

Import the package, write markup, done. The page you are reading is exactly that.

Any styling

Tokens are plain CSS custom properties — override them, bridge to utility frameworks, or theme per surface.

SSR: Lit 3 supports server rendering through @lit-labs/ssr, and the token layer is plain CSS that ships as-is — no runtime theme JavaScript either way.

Built like production infrastructure

Professional is not a coat of paint — it is the pipeline behind every pixel. These guarantees run on every push, not on release day.

Accessibility-first

An AA contrast ledger, axe scans in both themes, screen-reader semantics, full keyboard parity and reduced-motion support baked into every component.

Real dark mode

One attribute — data-theme="dark" — re-maps the semantic token layer; shadows collapse into tonal elevation. No second stylesheet, no code branches.

Token pipeline, not hex soup

258 tokens generated from a single DESIGN source; CI fails on hard-coded values inside the packages, so drift cannot land.

Verified on every push

2,755 automated visual and axe checks compare every component against committed cross-platform baselines — light and dark.

Generated React surface

Wrappers come from the Custom Elements Manifest, so the React API cannot drift from the Lit core; events arrive with unwrapped payloads.

Shared overlay controller

Modals, popovers, tooltips and toasts share one z-index and focus-return discipline — stacking contexts never fight.

A taste of the API

Same component, two surfaces — the custom element and the generated React wrapper. The kit installs as a pnpm workspace link from a pinned release tag; the full recipe lives in the README quick start.

index.html — any framework 
<!-- tokens once, components once -->
<!-- then markup is the API -->
<tk-button variant="primary" size="hero">Open an account</tk-button>

<tk-input label="Email" placeholder="name@example.com"></tk-input>
App.tsx — React wrapper 
// generated from the Custom Elements Manifest
import 'pillkit-tokens/tokens.css';
import 'pillkit-components';
import { Button, Input } from 'pillkit-react';

<Button variant="primary" size="hero">Open an account</Button>
<Input label="Email" placeholder="name@example.com" />
