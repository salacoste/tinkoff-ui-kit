# Участие в разработке

Спасибо за интерес к pillkit. Проект учебный и развивается очерёдными
специфицированными окнами, но баг-репорты, фиксы и предложения компонентов
приветствуются. Ниже — минимум, без которого PR не пройдёт CI и ревью.

## С чего начать

1. Прочитайте [README.md](README.md) (структура, быстрый старт потребителя) и
   этот файл целиком.
2. Для погружения в архитектуру и процесс — [HANDOFF.md](HANDOFF.md).
3. Контракт API компонентов (`packages/components/CONVENTIONS.md`, разделы
   §4 «API» и §9 «Замороженные решения») — **FROZEN**: изменения этих разделов
   возможны только отдельным решением мейнтейнера.

## Окружение

- Node >= 20, **pnpm** (приходит через `packageManager` + corepack).
- **npm не используется никогда** — ни для установки, ни для публикации.
- Подъём: `pnpm install && pnpm build && pnpm test` — это зелёный baseline.

## Порядок команд (важно)

Генерация идёт **до** тестов: `pnpm test` после `pnpm gen` — не наоборот
(gen-drift проверяется по свежесгенерированным файлам).

```bash
pnpm gen && pnpm gen:tokens   # регенерация CEM/обёрток и токенов
pnpm build && pnpm test && pnpm lint && pnpm typecheck
pnpm test:visual              # визуальная регрессия + axe, обе темы
```

- Правка любого компонентного `*.css.ts` → обязательно `pnpm gen` в том же
  PR (сгенерированные файлы коммитятся вместе с изменением).
- Правка `DESIGN.md` → `pnpm gen:tokens` **и** `pnpm gen`.
- `dist/` руками не правится — только генераторами.
- В tsconfig действует `experimentalDecorators: true` — это единственный
  рабочий путь Lit на текущем стеке; не «чините».
- Порт `6007` машинно-глобален для `test:visual`: не запускайте два прогона
  параллельно (гард tree-identity прервёт прогон против чужого дерева).

## Базлайны (визуальная регрессия)

- Compare-режим не перезаписывает PNG с расхождением ниже 1.5% — если правка
  осознанно меняет рендер, **удалите затронутые PNG явно** и переснимите
  (`pnpm test:visual:update` или точечно `playwright test --update-snapshots -g "<story-id>"`).
- Новые истории получают базлайны автоматически при отсутствии PNG.
- Не переименовывайте базлайны руками — имя производно от story-id.

## Языки и коммиты

- Контент историй — русский; story-meta (titles), код, коммиты — английский.
- Коммиты — conventional (`feat:`, `fix:`, `docs:`, `chore:` …), scope по пакету.
- В публикуемых строках (имена, описания, доки) — ноль товарных знаков
  Т-Банка вне фактологических URL и дисклеймера README.

## Доступность

Каждая поверхность проверяется в **обеих темах**: axe, контраст (WCAG AA),
клавиатурный контракт, reduced-motion. Новые компоненты следуют гейту
компонента (FR-16: impeccable, стори с a11y-разделом и SR-протоколом,
React-обёртка из CEM, side-by-side против эталона).

## Юридические границы (не обходить)

- **Шрифты DaytonaSans/DaytonaPragma — отдельно лицензированы** (© Monotype /
  © ParaType), не MIT, не переотправляются и не переименовываются; условия —
  `packages/tokens/fonts/LICENSE-FONTS.md`.
- **Личные данные (ПД) в материалы issue/PR не вставляются**: скриншоты
  авторизованных поверхностей — только в полностью редактированном виде.
- Вендорные `transitions/t-*.css` не переиздаются как отдельная библиотека.

## Issues и PR

- **Баг** — шаблон bug report: тег версии кита (`git describe --tags`), тема,
  минимальный воспроизводимый пример.
- **Предложение компонента** — шаблон component request: референс-поверхность,
  скриншот эталона, чего не хватает существующему набору.
- PR: зелёный CI обязателен (вердикт Actions, не локальный прогон); описание —
  что и зачем, ссылка на issue; чеклист ниже.

### Чеклист PR

- [ ] `pnpm gen` / `pnpm gen:tokens` выполнены после правок css.ts / DESIGN.md
- [ ] `pnpm build && pnpm test && pnpm lint && pnpm typecheck` — зелёные
- [ ] `pnpm test:visual` зелёный; осознанные изменения рендера — PNG пересняты явно
- [ ] Обе темы, axe и клавиатура проверены для затронутых поверхностей
- [ ] API-изменения соответствуют CONVENTIONS §4/§9 (или отдельное решение)
- [ ] Товарные знаки / ПД / шрифтовые границы соблюдены
