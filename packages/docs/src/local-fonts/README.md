# Локальные шрифты (не публикуются)

Папка для шрифтов, которые рендерятся в доках **только на твоей машине** и
никогда не попадают в публичный пакет/репозиторий (`local-fonts.css` и все
`*.woff2` gitignored).

## Как включить

1. Получи лицензионные woff2 (см. «Где брать» ниже) и положи их в эту папку.
2. Скопируй `local-fonts.example.css` → `local-fonts.css`. В шаблоне два режима:
   **A** — канонические family-имена (токены подхватят сами, ноль правок);
   **B** — свои псевдонимы (например `DaytonaSans`/`DaytonaPragma`) + переопределение
   слотов `--tk-font-heading`/`--tk-font-body` в конце файла (файл грузится после
   tokens.css — каскад на нашей стороне).
3. Перезапусти `pnpm --filter pillkit-docs dev` — preview подхватит файл
   автоматически (import.meta.glob).

Шаблон использует канонические family-имена сайта (`dsHeading`, `TinkoffSans`,
`haas`, `"Neue Haas Unica W1G"`, `pragmatica`) — с ними токен-слоты подхватывают
шрифты без правок токенов. Family-имена в @font-face — interoperability, это
легально; незаконна раздача самих файлов без лицензии.

## Где брать (лицензии на web/embedding)

- **Neue Haas Unica W1G** — Monotype / myfonts.com (web-лицензия на домен).
- **Pragmatica** — paratype.ru (web-лицензия).
- **TinkoffSans** — проприетарный шрифт Т-Банка, в продаже нет; не используется.

## Важно

- Этот механизм нужен только для self-hosting оригиналов (например,
  TinkoffSans): бандлимые лицензированные DaytonaSans/DaytonaPragma китом
  (`packages/tokens/fonts/`, подключаются импортом
  `pillkit-tokens/daytona.css`) этот шаг не требуют.
- Даже для личного проекта файлы с чужого CDN без лицензии — нарушение.
  Лицензия Monotype/ParaType покрывает твой self-hosting — этого достаточно
  для механизма выше.
- Визуальный харнесс и CI всё равно пинят DaytonaSans (детерминированность) —
  локальные шрифты влияют только на живой просмотр дока.
