## 4. Controlled & uncontrolled *(inherited from the bank §4, frozen at 2.1 — Input PR)*

- Every stateful component ships BOTH modes with identical semantics *(AD-5)*. The bank shapes are inherited VERBATIM; ТЖ deviations go through the §9 exception log:
  - **Uncontrolled:** internal state; the initial value is the `defaultValue` prop (attribute `default-value`) — plain initial-value semantics, so changes after the first update are IGNORED. Consumer listens to `<prop>-change`. If both `value` and `defaultValue` are provided, `value` wins (controlled at first paint).
  - **Controlled — STRICT:** consumer sets `value` (a property channel; it never reflects); the element renders EXACTLY `value` and mutates nothing internally — interaction emits `<prop>-change` and applies nothing locally. For caret sanity the inner native control keeps its live text between updates and re-syncs to the value in force on the element's next update (mirroring how React wraps native inputs — consumers answering `<prop>-change` → setState get native-feeling behavior).
  - **Release:** removing `value` (setting it to null/undefined) switches the element to uncontrolled, with the internal state SEEDED from the last controlled value. Setting `value` again resumes strict rendering.
- On the React surface the wrapper applies the standard controlled mapping (`value` prop → element property, change event → handler with the unwrapped value) and adds NO value-clamping logic of its own; strict revert is the element's job, not the wrapper's.
- Which ТЖ surfaces are stateful channels at all — the ТЖ roster is display/link-heavy — `[RESOLVED — 16.1 freeze]` **NONE in the 16.1 roster.** The reading primitives are stateless display/link surface: `tj-prose` is a flow container that dispatches nothing; `tj-link` and `tj-cta` render native anchors and ride the native composed `click`. No controlled pairs, no exposed internal UI state. The first stateful ТЖ surface (16.4+ engagement bar / drawer / theme control) re-opens §4 on the ТЖ instance — `[re-opened and RESOLVED — 16.4]`, rows below.
- The first stateful ТЖ surface `[RESOLVED — 16.4]` **tj-composer — an ACTION surface, not a controlled pair.** The community fake-input card is a BUTTON, not an editor: no `value`/`defaultValue` and no controlled/uncontrolled distinction — §4's pair machinery does not apply because there is no value channel to control. Its whole contract is one occurrence event; the rows below freeze that grammar for every ТЖ successor:
  - **`label`** — string channel, NOT reflected (the §2 string-data rule inherited from the bank freeze); the default is the reference copy «Написать пост или вопрос…»; a non-empty label swaps the ghost text (the button's accessible name) verbatim. Emptying it is a story-documented contract edge: the consumer names the button themselves — a host `aria-label` forwards to the shadow button verbatim and WINS.
  - **`open-compose`** — bare-verb occurrence (§3/§9 grammar): `composed: true, bubbles: true`, NO `detail` — payload-less, so the frozen React unwrap contract passes the event itself to handlers (`onOpenCompose`). Activation changes NOTHING on the element: no editor, no open state, no focus move — opening the editor is consumer application logic.
  - **`TjX…Event` naming** — kit events ship an EXPORTED subclass of `CustomEvent` carrying `static readonly eventName` (first instance: `TjOpenComposeEvent`); the element dispatches the class and consumers may type listeners against it. The bank's plain `new CustomEvent('name', …)` idiom remains legal for ТЖ; the completeness net (`tests/tj-event-map-completeness.test.ts`) scans BOTH idioms and demands a registry entry for each.
  - The registry opened in step: `packages/tj-react/src/event-map.ts` first entry `'tj-composer': { onOpenCompose: 'open-compose' }` + `pnpm gen` — the 16.1 empty-registry machinery's predicted growth, proven by the populated case (generated wrapper files are unchanged; the runtime lookup in `createKitComponent` picks the prop up).
  - `tj-post-card` (the same story) stays a NO-ENTRY surface `[RESOLVED — 16.4]`: a transparent cell on the news-card anchor mold — navigation is the native anchor's own behavior; nothing dispatches.
- The 16.5 site chrome `[RESOLVED — 16.5]` — **two channels, one precedent each; navigation data stays prop-only.**
  - **tj-header `theme-change`** — the theme control's occurrence, `detail` a BARE STRING (`'auto' | 'light' | 'dark'`, the resulting mode — NOT a `{ value }` payload). The state lives on `document.documentElement[data-tj-theme]`, not on any element property, so this is not a `<prop>-change` value channel; the unwrap contract's object check fails on a string and React handlers receive the `TjThemeChangeEvent` itself (`onThemeChange`). The control is STATELESS by contract: every activation reads the attribute fresh, cycles `auto→light→dark→auto`, `auto` REMOVES the attribute (the auto leg is pure CSS `:not([data-tj-theme="light"])` + `prefers-color-scheme` — no-flash by construction, no matchMedia listener anywhere), then announces the resulting mode RU («Тема оформления: системная/светлая/тёмная») via an internal polite region. Out-of-band writes to the attribute can never desync the control — it remembers nothing.
  - **tj-rail `open` + `open-change`** — the overlay row of this file VERBATIM (reflected boolean property, `detail: { value: boolean }`, one dispatch site in `updated()` so burger/Esc/scrim/link/programmatic all emit; React handler receives the bare boolean via `onOpenChange`). Programmatic `open` works at ANY viewport — the burger is merely hidden ≥1200px; the sheet mechanics never consult the media query.
  - **`active-value` (tj-header) / `current-value` (tj-rail) are NOT channels** — plain input props the consumer sets from its router (never reflected, no event, exact-match against item `href` / item `value` respectively; unknown or value-less matches NOTHING). The §4 pair machinery does not apply: navigation chrome renders router state, it does not own it.

## 9. Freeze protocol *(inherited shape; the ТЖ instance freezes at 16.1)*

- The **React-surface API** (prop style, controlled-mode semantics, unwrapped-value handlers) and the **overlay usage API** are frozen in the BANK kit at Story 2.1 — Input PR (`packages/components/CONVENTIONS.md` §9). The ТЖ family INHERITS those shapes; it re-runs the freeze ritual on its own package's terms at **story 16.1 — the first stateful ТЖ component** (epics-v5 E16; AD-5 v5).
- Later ТЖ components conform to the frozen shapes. A deviation requires an entry in the exception log below with rationale and reviewer sign-off.

### Frozen React-surface API (inherited from the bank 2.1 freeze)

- Wrappers stay GENERATED from the ТЖ CEM manifest via `@lit/react` (the parameterized `generate-wrappers` machinery — AD-1 v5: not forked), with ТЖ kit custom events registered in the ТЖ-owned event-map `[RESOLVED — 16.1 freeze; OPENED — 16.4; grown — 16.5]` **the registry shipped EMPTY at 16.1 and opened at 16.4.** `packages/tj-react/src/event-map.ts` is `Object.freeze`d; its first entry is `'tj-composer': { onOpenCompose: 'open-compose' }` (the payload-less occurrence — handlers receive the `TjOpenComposeEvent` itself). 16.5 grew it to three tags — `'tj-header': { onThemeChange: 'theme-change' }` (bare-STRING detail → the event itself reaches handlers, the §4 row above) and `'tj-rail': { onOpenChange: 'open-change' }` (the overlay unwrap → bare boolean). The predicted growth held both times: appending entries + `pnpm gen` changed only the manifest and the new wrappers — generated files never reference the registry (the runtime lookup lives in `createKitComponent`).
- Handlers receive the UNWRAPPED `value` — `detail: { value }` is unwrapped by the wrapper runtime before the consumer's handler runs; the raw `CustomEvent` never reaches React code (AD-1). Payload-less kit events fall back to passing the event itself.
- Controlled mode on the React surface is the standard `value` + change-handler mapping onto the element (§4 strict semantics, enforced by the element; the wrapper adds NO value-clamping logic).
- The ТЖ payload-unwrap bridge (the bank's `kit-component.ts` mold) `[RESOLVED — 16.1 freeze]` **deliberate FR-17 duplication.** `packages/tj-react/src/kit-component.ts` duplicates the bank runtime contract (frozen at bank Story 2.1) because importing `pillkit-react` would be a forbidden tj→bank edge — the AD-12 drawer-helper precedent. The unwrap semantics are identical and frozen; any change here is a §9 exception-log entry, never a silent fork.

### Overlay usage API (inherited shape; the ТЖ instance is the rail's burger drawer)

- **Declarative-first.** An overlay surface is a normal element in the DOM tree whose open state is the `open` attribute/property plus an `open-change` event (`detail: { value: boolean }`, composed, bubbles). Content lives in SLOTS; the consumer owns the open state.
- **Imperative helpers ONLY for inherently imperative surfaces** (fire-and-forget notifications with nothing in the consumer's tree) — built on the SAME elements and events, never a parallel API.
- **The drawer ruling (AD-12 v5):** the ТЖ roster's only overlay-class surface is the rail's burger drawer. It gets a small ТЖ-owned overlay helper (mount + focus trap + scroll lock) inside THIS package — a deliberate, documented duplication of the bank controller's contract; importing `pillkit-components` would break FR-17. The helper's exact surface `[RESOLVED — 16.5]` **FROZEN: `src/overlays/` exports exactly THREE functions** — `mountSheet(el, { onScrimClick })` (scrim + popover/fixed ladder at `var(--tj-z-drawer)`, one-mount-one-release), `lockScroll()` (refcounted document lock), `trapFocus(el)` (Tab cycle + LIFO restore) — plus their handle types. TRANSLATED from the bank `src/overlays/`, never imported (FR-17); excluded from the CEM manifest (no element definitions) and re-exported through `src/index.ts`. The drawer owns every floating mechanic — `tj-rail` itself carries ZERO bespoke z/scroll/trap code and no z-index in its stylesheet. REVISIT trigger: a second ТЖ overlay surface → extract a shared `pillkit-overlays` package consumed by both families as a peer.
- Z-order only via `--tj-z-*` tokens `[RESOLVED — 16.1 freeze; minted — 16.5]` **the 16.5 opener minted the two-token scale:** `--tj-z-nav: 100` (sticky chrome — the one sanctioned non-overlay z consumption, `tj-header.css.ts`) and `--tj-z-drawer: 300` (the helper's sheet). Components never write z literals — the chrome sheet consumes `--tj-z-nav` bare, the helper consumes `--tj-z-drawer`; both consumptions are pinned by file in the consumed-tokens net.

## Naming quick-reference (inherited grammar, ТЖ namespace)

- Elements `tj-` prefix kebab-case (`tj-news-card`), classes `Tj` + PascalCase; one directory per component under `src/<name>/` with `index.ts`, styles module, `<name>.test.ts`, `<name>.stories.ts`.
- Value updates `<prop>-change` with `detail: { value }`; occurrences bare `<verb>`; kit events always `composed: true, bubbles: true`. The one sanctioned string-detail event is `theme-change` (16.5: document-root state, no element property — see the §4 row).
- Theming ONLY via `var(--tj-*)` tokens; per-component hooks follow `--tj-<component>-<slot>`; dark mode via the `[data-tj-theme="dark"]` token layer — zero component-level theme branches. No ТЖ component reads `--tk-*` and no bank component reads `--tj-*` (AD-2 v5).
