## Intent

**Problem:** Two generator-truth debts (epics-v3 9.2): (1) TOKEN_NOTES' AA-bearing
annotations are string literals inside `generate.mjs` — a DESIGN.md Colors-body edit changes
ZERO regenerated bytes and the annotations go silently stale; the review-added
`assertAnnotationConsistency` checks alias-to-scale EQUALITIES only, never
annotation↔DESIGN.md truth. (2) The AD-4 import matrix lives in THREE hand-maintained copies
(eslint.config.js patterns+messages, `AD4_MATRIX` in tests/import-boundaries.test.ts, README
prose) that already diverged once (spec-1.1: file-type/docs coverage).

**Approach:** (1) A new DESIGN.md frontmatter block `aa-annotations:` — the 9.1 fonts mold
(generator wired deliberately, unknown keys abort) — becomes the single machine source; the
AA-class TOKEN_NOTES entries DERIVE from it at generation (the literals die); every derived
note must still anchor in the Colors body (anchor lost → abort), so a body edit and the
generated truth can no longer diverge. (2) A root `ad4-matrix.mjs` module single-sources the
import matrix: eslint.config.js BUILDS its restriction blocks from it, the boundary test's
matrix/scan-roots derive from it, README's matrix lines are PINNED by a test against the
module's canonical directions string. Zero visual churn expected: notes reach only TOKENS.md
(no story renders them — verified this round); tokens.css/tokens.ts stay byte-stable.

## Boundaries & Constraints

- **`aa-annotations:` frontmatter block (the fonts mold):** map of semantic color name →
  `{ kind, status, story?, text }`. `kind` ∈ `override | addition | restricted | pairing |
  measured` (drives the note prefix); `status` ∈ `verified | assumed` (drives the
  [ASSUMPTION] flag machinery); `story` = closure pointer (e.g. `9.1`); `text` = the note
  body (prose, ratios included — moved verbatim from today's literals). Generator wiring is
  DELIBERATE: unknown top-level keys abort (house grammar), unknown entry fields abort,
  entry names must be declared color semantics.
- **The migrated set (frozen — exactly these 10 AA-bearing entries):** `text-secondary`,
  `focus-ring`, `link-on-tint`, `error-on-field`, `text-muted` (restricted), `delta-positive`,
  `delta-negative`, `tint-cream`, `tint-cream-raised`, `tint-brown`. Everything else in
  TOKEN_NOTES stays a literal by design (semantic-alias stories, probe-closure `Verified`
  Shapes/Colors entries, verbatim-extract entries, BLOCK_NOTE_SPACING).
- **Both-direction migration aborts:** a TOKEN_NOTES literal remaining for a name present in
  the block = double source → abort; an AA-class literal whose name is NOT in the block →
  abort (forces full migration of the 10). The class test "AA-bearing" = carries a contrast
  ratio or an AA ruling in its text.
- **Body anchor assert (the debt's core):** every derived note must trace to the DESIGN.md
  Colors body — the AA table row (or the frontmatter comment where the table has no row)
  must contain the entry's token ref plus at least one factual substring from `text` (a
  `N.NNN:1` ratio or a hex). Anchor lost → abort. Executor pins the exact substring
  mechanics in Implementation Notes; every one of the 10 must anchor on the FIRST run.
- **[ASSUMPTION] machinery:** `status: assumed` emits the flag in the note and counts in the
  TOKENS.md status line; `verified` (+ `story`) is the resolved form. The resolved-history
  line (TOKENS.md:9 today) is DERIVED from block+entry status, not hand-written. Zero open
  [ASSUMPTION]s exist today — the machinery proves itself via negative self-checks (below),
  not by holding live flags.
- **DARK_TOKEN_NOTES stay literals (recorded non-goal):** dark-side numbers are pinned in
  tests/contrast.test.ts — a stronger truth than prose parsing; deriving them would WEAKEN
  the guarantee.
- **AD-4 single-source:** new root `ad4-matrix.mjs` exporting: package dirs, per-package
  allowed specifiers, scan roots (incl. docs `.storybook`), file types, DERIVED
  `forbiddenGroups(pkg)` (all pillkit-\* minus self minus allowed), DERIVED
  `escapeRegexSource(pkg)`, and `CANONICAL_DIRECTIONS`
  ('components→tokens, react→components, docs→{react, components, tokens}'). A tiny
  `ad4-matrix.d.mts` type twin rides it; a runtime shape-assert pins twin↔module.
  `eslint.config.js` builds all package blocks programmatically from the module (messages
  embed CANONICAL_DIRECTIONS — the six hand-written copies of the directions string die).
  `tests/import-boundaries.test.ts` imports the matrix + scan roots (scanner logic and the
  synthetic negative checks stay in the test). A NEW test pins README carrying
  CANONICAL_DIRECTIONS verbatim (README edit rides this story if the current wording must
  move). ARCHITECTURE-SPINE.md is NOT machine-edited (planning artifact — intent record);
  the module's header comment points at its AD-4 record.
- **Coverage-gap class dies:** file types + scan roots defined ONCE — the 1.1 divergence
  (eslint missed docs/.storybook and file-type coverage) becomes structurally impossible;
  the test remains the precise net (path resolution), eslint the fast one (specifier shape).
- **Byte discipline:** regen diff = tokens.css/tokens.ts BYTE-IDENTICAL (notes never reach
  them — proven by git diff); TOKENS.md changes confined to the derived annotation rows +
  the status line; double-regen stable. **Zero PNG movement** (both themes, ×2 stable) — any
  PNG moving → STOP and investigate (notes render nowhere; movement = unintended coupling).
- **Gates:** gen:tokens BEFORE gen; pnpm test AFTER gen; full chain
  build→test→lint→typecheck; post-commit gen-drift (`pnpm gen && pnpm gen:tokens &&
  git diff --exit-code -- packages/ tests/`); visual ×2; `lsof -ti:6007` clean before each
  visual pass; CI green = Actions verdict (`gh run`) on the pushed head.
- **Non-goals:** no new tokens; no Colors-body table rewrite (the prose stays as the human
  narrative); no dark-note derivation; no eslint-engine lintText self-check (structure
  equality + existing synthetic checks suffice); no ARCHITECTURE-SPINE/README architecture
  rewrite beyond the canonical line; no baseline re-takes.
