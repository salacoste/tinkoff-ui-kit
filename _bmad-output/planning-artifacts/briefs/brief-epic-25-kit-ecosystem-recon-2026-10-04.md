## Метод: сначала класс источника, потом инструмент

Библиотеки — не недружелюбные страницы: они публикуют машиночитаемые
артефакты качественнее отрендеренного DOM. Инверсия приоритетов:

| Данные | Источник | Инструмент | Браузер? |
|---|---|---|---|
| Состав/версии/депы/лицензии/ритм | registry JSON API | HTTPS fetch | нет |
| API-поверхность (пропсы/события/слоты/типы) | tarball: `.d.ts`, CEM, `exports` | локальный парсинг | нет |
| Токены/темы | tarball: tokens.json, CSS custom props | локальный разбор | нет |
| Чейнджлоги/здоровье репо | GitHub (`gh api`) | API | нет |
| Docs IA/плейграунды/поведение | сайт доков | Playwright (наш молд) | да |
| Визуальный референс | примеры доков | Playwright + IM-паспорта | да |

Следствия: оси curl_cffi (TLS-имперсонация) и CloakBrowser (отпечаток)
для библиотек выпадают; Scrapy/Crawlee не нужны при ростере из десятков
целей — очередь/дедуп/резюм закрывает идемпотентный per-kit state;
Playwright — только слои «сайт/визуал». ~90% данных — без браузера,
детерминированно, диффабельно (JSON, не скриншот страницы).

## Standing laws + рамки эпика

- npm — never: registry доступ ТОЛЬКО HTTPS fetch (JSON/tarball),
  npm-CLI запрещён и здесь; pnpm — только локальные скрипты.
- ПД/лицензии: чтение публичных пакетов/репо чисто; в кит переносим
  факты/структуру/агрегаты, НЕ код; скриншоты доков — внутренний
  референс.
- Vision-бюджет: ≤2 на кит-ревью; композиты обязательны.
- CI не трогаем: миссия CI — релизные гейты; рекон — локальные
  скрипты, снапшот коммитится как данные.
- Инструмент дев-only: ноль правок `packages/*`, снапшоты не входят
  в публикуемые артефакты.
- 24T параллельно паркуется (капчуры мейнтейнера), не блокирует и
  не блокируется эпиком.
- Новых продуктовых историй из находок — БЕЗ нового брифа не открывать.

## Носитель/механика

`recon/` (корень репо, TS, запуск `pnpm recon:*` из корневого
package.json): `recon/snapshots/*.jsonl` — снапшоты (кит+версия+fetchedAt
в каждой записи), `recon/roster.yml` — ростер; отчёты — в
`_bmad-output/planning-artifacts/`. Идемпотентность: повторный прогон
той же версии — нулевой дифф.
